# 나만의 Neovim 환경 만들기: 시작 로드맵

이 프로젝트의 목표는 단순히 플러그인이 많은 Neovim을 만드는 것이 아니다.

Vim의 편집 문법을 제대로 익히고, 실제 작업에서 반복되는 불편함을 하나씩 해결하면서 마우스 없이 키보드와 터미널만으로 대부분의 개발 작업을 처리할 수 있는 환경을 만드는 것이 목표다. 터미널은 Ghostty를 사용한다.

## 1단계: Vim의 편집 언어 익히기

먼저 `h`, `j`, `k`, `l`보다 중요한 Vim의 동작 조합을 익힌다.

Vim 명령은 대체로 다음 구조를 가진다.

```text
숫자 + 동작(operator) + 이동(motion)
```

예시:

```vim
w       다음 단어로 이동
b       이전 단어로 이동
e       단어 끝으로 이동

dw      다음 단어까지 삭제
d$      줄 끝까지 삭제
ciw     현재 단어를 지우고 입력
3dd     세 줄 삭제
yap     문단 전체 복사
```

이 단계에서 익힐 핵심 명령은 다음과 같다.

- `w`, `b`, `e`, `0`, `^`, `$`, `%`
- `f`, `t`, `F`, `T`와 `;`, `,`
- `gg`, `G`, `{`, `}`
- `d`, `c`, `y` operator
- `i`, `a` text object
- `u`, `<C-r>`, `.`
- `/`, `?`, `n`, `N`
- Visual mode 없이 대상을 선택하고 수정하는 방법

특히 `ciw`, `ci"`, `da(`처럼 텍스트 객체를 대상으로 편집하는 습관을 들인다.

목표는 “어떻게 선택하지?”가 아니라 “무엇을 어떻게 바꾸지?”라고 생각하는 것이다.

## 2단계: Neovim 기본 설정 만들기

Vim 조작이 조금 익숙해지면 최소한의 Lua 설정을 만든다.

초기 설정 범위는 다음 정도로 제한한다.

- 줄 번호와 상대 줄 번호
- 들여쓰기 규칙
- 검색 동작
- 시스템 클립보드
- leader 키
- 창과 버퍼 이동 키
- 진단하기 편한 기본 UI
- 설정 파일 모듈화

이 단계에서는 플러그인 관리자를 추가하더라도 플러그인은 거의 설치하지 않는다. 기본 기능과 플러그인 기능을 구분할 수 있어야 나중에 문제가 생겼을 때 직접 원인을 찾을 수 있다.

## 3단계: 파일과 프로젝트 탐색

마우스를 없애려면 편집뿐만 아니라 이동 비용을 줄여야 한다.

다음 작업 흐름을 구축한다.

- 파일 이름으로 검색
- 프로젝트 전체 문자열 검색
- 열린 버퍼 사이 이동
- 이전 위치와 다음 위치 이동
- 정의, 참조, 진단 위치로 이동
- 여러 창을 만들고 크기와 위치 제어
- 필요한 경우 파일 탐색기 사용

이 단계에서는 fuzzy finder와 빠른 검색 도구를 연결한다.

```text
Ghostty
  └─ Neovim
      ├─ 파일 검색
      ├─ 프로젝트 전체 검색
      ├─ 버퍼 이동
      └─ 코드 위치 이동
```

파일 트리를 계속 펼치는 대신 찾고 싶은 대상을 이름이나 내용으로 즉시 호출하는 것을 목표로 한다.

## 4단계: 코드 편집 환경 구축

프로젝트 탐색에 익숙해진 뒤 IDE 기능을 추가한다.

- Treesitter 기반 구문 분석
- LSP 기반 자동완성과 진단
- 정의 및 참조 이동
- 이름 변경
- 코드 액션
- 자동 포매팅
- 프로젝트별 formatter와 linter
- snippets
- 테스트 실행

모든 언어를 미리 지원하지 않는다. 실제로 사용하는 언어를 하나씩 추가하고 언어마다 다음 항목을 확인한다.

```text
LSP        → 진단, 정의 이동, 이름 변경
Formatter  → 코드 서식
Linter     → 정적 검사
Test runner → 테스트 실행과 실패 위치 이동
Debugger   → 실제로 필요할 때 도입
```

## 5단계: Git과 터미널 작업 통합

Neovim과 Ghostty를 하나의 작업 환경으로 연결한다.

- 변경된 줄 확인
- hunk 단위 stage/reset
- diff 보기
- commit 내역 확인
- 터미널에서 테스트 및 빌드
- 실패 메시지에서 해당 파일과 줄로 이동
- 필요한 경우 `tmux` 또는 Neovim 내 터미널 도입

`tmux`는 처음부터 도입하지 않는다. Ghostty의 탭과 창으로 시작한 뒤 세션 유지나 원격 작업이 실제로 필요해질 때 추가한다.

## 6단계: 반복 작업 자동화

기본 조작이 몸에 익으면 반복되는 작업을 자동화한다.

- 레지스터와 클립보드 구분
- 매크로 녹화와 반복
- quickfix/location list
- 여러 파일에 걸친 치환
- 반복 가능한 사용자 명령
- 프로젝트별 실행 명령
- 세션 복원
- 자주 쓰는 작업을 keymap이나 command로 승격

한 번 수행한 작업을 바로 키맵으로 만들지는 않는다. 여러 번 반복되어 불편함이 확인된 작업만 자동화한다.

## 프로젝트 진행 원칙

1. 한 번에 하나의 문제만 해결한다.
2. 새로운 키맵에는 반드시 이유를 기록한다.
3. 기본 Vim 명령으로 충분하면 키맵을 추가하지 않는다.
4. 플러그인은 해결하려는 문제가 명확할 때만 설치한다.
5. 설정 변경 후에는 실제 작업을 해보고 평가한다.
6. 익숙하지 않은 기본 명령을 키맵으로 덮어쓰지 않는다.
7. 다른 사람의 설정을 그대로 복사하지 않고 필요한 부분만 가져온다.

설정 파일은 결과물인 동시에 학습 기록으로 관리한다. 각 결정에 “왜 이 설정을 사용했는가”를 남겨 향후 유지보수가 가능하도록 한다.

## 반복할 작업 사이클

각 단계는 다음 사이클로 진행한다.

```text
불편함 발견
   ↓
Vim/Neovim 기본 기능 확인
   ↓
필요하면 설정 또는 플러그인 후보 비교
   ↓
최소한으로 적용
   ↓
실제 작업에서 사용
   ↓
유지·수정·제거 결정
```

매 단계마다 다음 세 가지를 함께 다룬다.

- 새로 익힐 Vim 명령 3~5개
- 해결할 실제 불편함 한 가지
- 설정에 추가할 기능 한 가지

첫 번째 실습 단계에서는 설정을 거의 변경하지 않고 `operator + motion + text object`를 익히면서 현재 환경과 주로 사용할 프로그래밍 언어를 조사한다. 그다음 최소한의 `init.lua`를 설계하고, 설정 하나하나의 의미를 확인하면서 확장해 나간다.
